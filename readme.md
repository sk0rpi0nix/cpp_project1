# Личный учёт трат — простой HTTP-сервер на Go

Учебный проект первого этапа. Это маленький веб-сервер на чистом Go, без сторонних библиотек. Он умеет отвечать на три адреса и показывает, как вообще работает HTTP-сервер «под капотом».

## Что нужно, чтобы запустить

- Установленный **Go** (проверить: `go version`)
- Терминал

## Как запустить

В папке с проектом:

```bash
go mod init expenses   # делается один раз, создаёт файл go.mod
go run .
```

После запуска в терминале появится:

```
server is listening on port 8080...
```

Значит, сервер работает. Открой в браузере или проверь через `curl`.

## Какие адреса (маршруты) есть

| Адрес     | Метод  | Что вернёт                                          |
|-----------|--------|-----------------------------------------------------|
| `/`       | GET    | Текст-приветствие                                   |
| `/about`  | GET    | Короткое описание проекта                           |
| `/ping`   | GET    | `pong` и статус 200 OK                              |
| `/ping`   | НЕ GET | Статус 405 (метод не разрешён), тело пустое         |

### Как проверить через curl

```bash
curl -i http://localhost:8080/
curl -i http://localhost:8080/about
curl -i http://localhost:8080/ping
curl -i -X POST http://localhost:8080/ping   # должен вернуть 405
```

Флаг `-i` показывает **заголовки** ответа — там видно статус-код (`200 OK`, `405 Method Not Allowed`).

## Отчёт: что происходит с запросом от начала до конца

Разберём по шагам, что случается, когда ты открываешь в браузере, например, `http://localhost:8080/ping`.

**1. Браузер отправляет запрос.**
Браузер говорит серверу: «Дай мне страницу по адресу `/ping`, методом GET». Это уходит по сети на порт `8080`.

**2. Сервер принимает запрос.**
Программа на Go уже «слушает» этот порт (это делает `http.ListenAndServe(":8080", nil)`). Как только запрос пришёл — сервер просыпается и смотрит: «А по какому адресу пришли?»

**3. Выбирается обработчик (функция-маршрут).**
Дальше в дело вступает `http.ServeMux` — это встроенный «распределитель». Ему заранее сказали:

- если путь `/` → вызови `handler`
- если путь `/about` → вызови `abouthandler`
- если путь `/ping` → вызови `pinghandler`

`ServeMux` сравнивает путь из запроса со списком и вызывает нужную функцию.

**4. Функция-обработчик получает две вещи.**
В неё приходят два параметра:

- `w http.ResponseWriter` — «ручка», через которую сервер пишет ответ клиенту. Всё, что ты запишешь в `w`, уйдёт в браузер.
- `r *http.Request` — сам запрос: какой метод (GET/POST и т.д.), какой путь, какие заголовки, что в теле.

**5. Обработчик решает, что делать, и пишет ответ.**
Например, `pinghandler` смотрит на `r.Method`. Если это `GET` — ставит статус `200` и пишет `pong`. Если другой — ставит статус `405`.

**6. Сервер отправляет ответ обратно.**
Всё, что было записано в `w`, упаковывается в HTTP-ответ: сначала строка статуса (например, `HTTP/1.1 200 OK`), потом заголовки, потом тело (`pong`). Оно уходит в браузер.

**7. Браузер показывает результат.**
На экране появляется `pong`.

## Почему `ResponseWriter` важен

`ResponseWriter` — это единственный «канал», через который сервер может что-то сказать клиенту. Если не вызвать ни одного метода записи (`Write`, `WriteHeader`, `Fprintln` и т.п.):

- Go по умолчанию отправит статус **200 OK** и **пустое тело**.
- То есть клиент получит «нормальный» ответ, но без содержимого. Иногда это выглядит как пустая белая страница — и непонятно, что вообще пошло не так.

Поэтому: если хочешь что-то вернуть клиенту — обязательно пиши в `w`.

## GET и POST — в чём разница и когда что использовать

Простыми словами:

- **GET** — «дай мне данные». Ничего не меняет на сервере. Параметры передаются прямо в адресе (`/items?id=5`).
- **POST** — «прими и обработай данные». Обычно что-то создаёт или меняет. Данные передаются в теле запроса, а не в адресе.

Примеры:

| Задача                     | Метод     |
|----------------------------|-----------|
| Показать список трат       | GET       |
| Открыть одну трату по id   | GET       |
| Добавить новую трату       | POST      |
| Изменить существующую      | PUT/PATCH |
| Удалить трату              | DELETE    |

Бытовое правило: если после запроса на сервере ничего не поменялось — это **GET**. Если поменялось (создалась запись, отправилось письмо, списались деньги) — почти наверняка **POST** или другой «изменяющий» метод.

## Структура проекта

```
.
├── go.mod       # описание модуля (создаётся командой go mod init)
├── main.go      # весь код сервера
└── README.md    # этот файл
```

Пока всё в одном файле `main.go` — так проще разобраться. Дальше, когда появятся новые этапы, код будет разбит по папкам.

## Что использовалось

- `net/http` — стандартный пакет Go для HTTP (сервер, маршрутизация, запросы, ответы).
- `fmt` — печать текста в ответ и в консоль.
- Только стандартная библиотека, никаких внешних зависимостей.

## Что можно улучшить дальше

- Вынести обработчики в отдельные файлы / пакеты.

- Добавить логирование запросов (метод, путь, статус, время ответа).
- Добавить реальные данные о тратах и подключить базу.
